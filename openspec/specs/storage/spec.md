# Storage (Хранение данных)

## Purpose

Описание структуры хранения данных Salary Buddy: ключи localStorage, идентификаторы сущностей, правила валидации при загрузке и поведение при ошибках хранилища. Приложение работает без бэкенда — все данные хранятся локально в браузере.

## Requirements

### Requirement: Хранение в localStorage

Система MUST сохранять все данные пользователя в `localStorage` браузера с префиксом ключа `salary-buddy:`. Каждый тип данных хранится в отдельном ключе как JSON-массив или JSON-объект. При загрузке приложения данные восстанавливаются из хранилища.

| Ключ localStorage | Содержимое |
|---|---|
| `salary-buddy:salary-changes` | Массив записей об окладе (SalaryChange[]) |
| `salary-buddy:salary-payment-settings` | Объект настроек выплаты (SalaryPaymentSettings) |
| `salary-buddy:surcharges` | Массив записей доплат (SurchargeChange[]) |
| `salary-buddy:bonuses` | Массив премий (Bonus[]) |
| `salary-buddy:vacations` | Массив отпусков (Vacation[]) |
| `salary-buddy:sick-leaves` | Массив больничных (SickLeave[]) |
| `salary-buddy:sick-leave-settings` | Объект настроек доплаты по больничному (SickLeaveSettings) |
| `salary-buddy:payments` | Массив рассчитанных платежей (Payment[]) |

#### Scenario: Успешное сохранение и восстановление

- **GIVEN** пользователь добавил запись об окладе и закрыл браузер
- **WHEN** пользователь открывает приложение заново
- **THEN** запись об окладе восстановлена из localStorage без потерь

#### Scenario: Пустое хранилище при первом запуске

- **GIVEN** localStorage не содержит ключей с префиксом `salary-buddy:`
- **WHEN** пользователь открывает приложение впервые
- **THEN** приложение загружается с пустыми данными, ошибки не возникает

### Requirement: Структура идентификаторов сущностей

Система MUST присваивать каждой создаваемой сущности уникальный идентификатор по шаблону `{тип}:{год}:{порядковый_номер}`. Порядковый номер начинается с 01 и увеличивается для каждого нового объекта в рамках года.

| Сущность | Шаблон ID | Пример |
|---|---|---|
| Запись об окладе | `sal:{year}:{seq}` | `sal:2026:01` |
| Премия | `bon:{year}:{seq}` | `bon:2026:03` |
| Отпуск | `vac:{year}:{seq}` | `vac:2026:01` |
| Больничный лист | `sick:{year}:{seq}` | `sick:2026:02` |
| Доплата | `sur:{year}:{seq}` | `sur:2026:01` |

Год в идентификаторе — год даты вступления в силу (для оклада и доплат) или год начала периода (для премий, отпусков, больничных).

#### Scenario: Нумерация внутри года

- **GIVEN** в 2026 уже есть отпуск `vac:2026:01`
- **WHEN** пользователь создаёт второй отпуск в 2026
- **THEN** присвоен ID `vac:2026:02`

#### Scenario: Сброс нумерации в новом году

- **GIVEN** последний отпуск 2025 — `vac:2025:05`
- **WHEN** пользователь создаёт первый отпуск 2026
- **THEN** присвоен ID `vac:2026:01`

### Requirement: Source ID расчётных платежей

Система MUST присваивать каждому рассчитанному платежу sourceId, который связывает платёж с источником. Source ID используется для отслеживания фактических сумм и каскадного перерасчёта.

| Тип платежа | Шаблон sourceId | Пример |
|---|---|---|
| Аванс | `sal:{year}:{month}:a` | `sal:2026:03:a` |
| Зарплата | `sal:{year}:{month}:b` | `sal:2026:03:b` |
| Премия | ID премии | `bon:2026:01` |
| Отпускные | ID отпуска | `vac:2026:01` |
| Доплата | `sur:{year}:{month}` | `sur:2026:03` |
| Пособие работодателя | `{sickId}:emp:{year}-{month}:{half}` | `sick:2026:01:emp:2026-07:a` |
| Пособие СФР | `{sickId}:sfr:{year}-{month}` | `sick:2026:01:sfr:2026-07` |
| Доплата до оклада | `{sickId}:topup:{year}-{month}:{half}` | `sick:2026:01:topup:2026-07:b` |

Значение `{half}` — половина месяца: `a` (дни 1–15) или `b` (дни 16+).

#### Scenario: Уникальность sourceId

- **GIVEN** два платежа за один месяц: аванс и зарплата
- **THEN** sourceId различаются суффиксом: `sal:2026:03:a` и `sal:2026:03:b`

### Requirement: Идентификаторы платежей в хранилище

Система MUST присваивать каждому платежу уникальный ID при сохранении. Если несколько платежей приходится на одну дату, к ID добавляется порядковый номер для разрешения коллизий.

#### Scenario: Уникальный ID платежа

- **GIVEN** платёж 15.03.2026
- **THEN** ID содержит дату и уникальный суффикс (например, `pay:2026-03-15:0`)

#### Scenario: Коллизия дат

- **GIVEN** два платежа на 15.03.2026 (аванс + премия)
- **THEN** каждый платёж имеет уникальный ID с разным порядковым номером

### Requirement: Валидация данных при загрузке

Система MUST валидировать данные из localStorage при каждой загрузке с помощью схем zod. Если данные не проходят валидацию (повреждены, устаревший формат), система должна сбросить хранилище для этого ключа и продолжить работу с пустыми данными.

#### Scenario: Корректные данные

- **GIVEN** localStorage содержит валидный JSON массив премий
- **WHEN** приложение загружается
- **THEN** премии восстановлены успешно

#### Scenario: Повреждённые данные

- **GIVEN** localStorage содержит невалидный JSON для ключа bonuses
- **WHEN** приложение загружается
- **THEN** данные по премиям сброшены, остальные данные восстановлены, приложение работает

### Requirement: Фактическая сумма платежа (fact)

Система MUST хранить фактическую сумму gross подтверждённую пользователем как поле `fact` в объекте Payment. Если факт не установлен — поле отсутствует или равно undefined. Факт влияет на расчёт НДФЛ и каскадный перерасчёт последующих платежей.

#### Scenario: Установка факта

- **GIVEN** платёж gross = 50 000, пользователь подтвердил net = 43 500
- **THEN** fact сохранён как рассчитанный gross (≈ 50 000), используется в каскадном перерасчёте

#### Scenario: Отсутствие факта

- **GIVEN** платёж без подтверждения пользователя
- **THEN** факт отсутствует, расчёт использует gross из расчёта

### Requirement: Поведение при ошибке хранилища

Система MUST обрабатывать ошибки localStorage (квота исчерпана, недоступное хранилище) gracefully. При ошибке сохранения — показать уведомление пользователю. При ошибке загрузки — продолжить с пустыми данными.

#### Scenario: Превышение квоты

- **GIVEN** localStorage заполнен до лимита
- **WHEN** пользователь добавляет новую запись
- **THEN** показана ошибка, данные не потеряны в памяти приложения
