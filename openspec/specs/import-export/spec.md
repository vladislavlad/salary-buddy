# Import / Export (Экспорт и импорт данных)

## Purpose

Экспорт всех данных Salary Buddy в JSON-файл для резервного копирования и переноса между устройствами. Импорт из JSON-файла с полной заменой текущих данных.

## Requirements

### Requirement: Экспорт всех данных в JSON

Система MUST экспортировать все данные пользователя в один JSON-файл, включающий дату экспорта и полные массивы всех сущностей. Формат файла — валидный JSON, валидируемый схемой zod.

Экспортируемые разделы:
- Настройки выплаты (salaryPaymentSettings)
- Оклады (salaries)
- Премии (bonuses)
- Отпуска (vacations)
- Доплаты (surcharges)
- Платежи (payments)
- Больничные листы (sickLeaves)
- Настройки доплаты по больничному (sickLeaveSettings)

#### Scenario: Успешный экспорт

- **GIVEN** пользователь имеет 3 оклада, 2 премии и 1 отпуск
- **WHEN** инициирован экспорт
- **THEN** сгенерирован JSON-файл со всеми данными и датой экспорта в формате YYYY-MM-DD

#### Scenario: Экспорт пустых данных

- **GIVEN** пользователь не добавил ни одной записи
- **WHEN** инициирован экспорт
- **THEN** сгенерирован JSON с пустыми массивами и настройками по умолчанию

### Requirement: Импорт из JSON с полной заменой

Система MUST загружать данные из JSON-файла, валидировать их схемой zod и полностью заменять текущие данные в хранилище. Каждая секция данных записывается целиком, заменяя содержимое соответствующего ключа хранилища; предварительная очистка хранилища не выполняется.

#### Scenario: Успешный импорт

- **GIVEN** пользователь выбирает файл с валидным JSON
- **WHEN** завершена загрузка файла
- **THEN** текущие данные заменены импортированными, приложение отображает новые данные

#### Scenario: Ошибка валидации при импорте

- **GIVEN** файл содержит невалидный JSON (отсутствует обязательное поле)
- **WHEN** пользователь пытается импортировать
- **THEN** показана ошибка, текущие данные сохранены без изменений

#### Scenario: Невалидный формат файла

- **GIVEN** файл не является корректным JSON
- **WHEN** пользователь пытается импортировать
- **THEN** показана ошибка парсинга, текущие данные сохранены

### Requirement: Структура экспортируемого файла

Система MUST формировать JSON со следующей структурой верхнего уровня. Поле `exportDate` — дата создания резервной копии в формате YYYY-MM-DD. Массивы сущностей содержат полные объекты с идентификаторами, датами и рассчитанными полями.

```json
{
  "exportDate": "2026-07-15",
  "salaryPaymentSettings": { ... },
  "salaries": [ ... ],
  "bonuses": [ ... ],
  "vacations": [ ... ],
  "surcharges": [ ... ],
  "payments": [ ... ],
  "sickLeaves": [ ... ],
  "sickLeaveSettings": { ... }
}
```

#### Scenario: Дата экспорта

- **GIVEN** экспорт выполнен 15 июля 2026
- **THEN** поле exportDate = "2026-07-15"

### Requirement: Настройки по умолчанию при импорте

Система MUST подставлять значения по умолчанию для настроек, отсутствующих в импортируемом файле. Если `sickLeaveSettings` отсутствует — используется значение по умолчанию (доплата отключена, лимит 20 дней). Если `salaryPaymentSettings` отсутствует — используются настройки по умолчанию приложения.

#### Scenario: Отсутствующие настройки больничного

- **GIVEN** импортируемый файл не содержит sickLeaveSettings
- **THEN** загружены значения по умолчанию: доплата отключена, лимит 20 рабочих дней в году

### Requirement: Порядок операций при импорте

Система MUST выполнять импорт полной записью: при записи секции всё содержимое соответствующего ключа хранилища заменяется (массив — целиком, настройки — целиком). Система MUST NOT очищать хранилище до валидации и записи импортированных данных. Если запись одной из секций завершилась ошибкой, незаписанные секции сохраняют предыдущие данные.

#### Scenario: Полная замена секций

- **GIVEN** текущие данные: 5 окладов, 3 премии
- **WHEN** импортированы данные: 2 оклада, 1 премия
- **THEN** после импорта: ровно 2 оклада и 1 премия, старые записи удалены

#### Scenario: Ошибка записи части секций

- **GIVEN** произошла ошибка при записи одной из секций
- **WHEN** импорт прерван
- **THEN** незаписанные секции сохраняют предыдущие данные, пользователю показана ошибка
