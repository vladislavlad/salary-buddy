# Design: Единая таблица настроек по годам

## Context

Годозависимые настройки сейчас живут в трёх местах (см. proposal.md — Why):

- `src/features/payments/model/calculation/sickLeaveLimits.ts` — `MROT_BY_YEAR` (2024–2026, руб.), `CONTRIBUTION_BASE_BY_YEAR` (2022–2025, руб.), производные формулы лимитов СДЗ
- `src/features/payments/model/ndfl.ts` — `NDFL_PROGRESSIVE_1/2`, `NDFL_CONFIGS` (2023–2026, копейки), `RC_BASE_BRACKETS`
- `src/features/payments/model/calculation/sick-leave.ts` — `WORK_INJURY_MONTHLY_CAP_KOP` (константа 2026, копейки)
- `src/features/payments/model/calculation/index.ts:557-559` — `rcBaseFromYear = 2026 : 2025` (границы лет отдельной базы РК захардкожены)
- `src/shared/lib/utils.ts:21-22` — `MIN_DISPLAY_YEAR = 2024` / `MAX_DISPLAY_YEAR = 2027` (границы диапазона приложения: навигация в `App.tsx`, диапазон расчёта в `index.ts:620-621`, загрузка календарей в `CalendarProvider.tsx`)

Ограничения: строгий TypeScript без `any`; `shared/` — только для мульти-фичевых модулей (AGENTS.md); расчётные формулы (СДЗ, НДФЛ, отпускные) не меняются — переезжает только данные.

## Goals / Non-Goals

**Goals:**
- Один модуль-реестр с таблицей «год → настройки» для 2024–2027 (2027 — частичная строка: только уже установленные значения); все потребители читают из него
- Годозависимый потолок по производственной травме с правилом января (индексация с 1 февраля)
- Добавление нового года = одна строка в таблице (сразу или по частям, по мере установления значений)
- Диапазон поддерживаемых лет приложения (MIN/MAX_DISPLAY_YEAR) выводится из ключей таблицы

**Non-Goals:**
- Изменение расчётных формул, localStorage-форматов, UI
- Поддержка годов до 2024 в режиме «полной точности» (fallback на 2024)

## Decisions

### D1. Расположение: `src/shared/lib/yearSettings.ts`

Реестр кладём в `shared/lib/`: потребители — фича `payments` (расчёты), фича `calendar` (диапазон загрузки календарей) и `App.tsx` (навигация) — через MIN/MAX_DISPLAY_YEAR, выводимые из ключей таблицы (D7). Мульти-фичевое использование — именно тот случай, для которого `shared/` разрешён (AGENTS.md). Импорт из `calendar`/`App` в `features/payments` нарушал бы самодостаточность фич.

Альтернативы:
- `payments/model/yearSettings.ts` — отклонено: MIN/MAX из ключей таблицы потребовали бы кросс-фичевых импортов.
- Захардкоженные MIN/MAX в `shared/utils.ts` + тест-синхронизация с таблицей — отклонено по решению пользователя: «добавление года» должно меняться в одном месте.

### D2. Форма данных: частичные строки + per-field fallback

```ts
export interface YearSettings {
  mrotKop: number;                    // МРОТ, коп/мес
  workInjuryMonthlyBenefitKop: number; // макс. ежемесячная страховая выплата, коп/мес
  ndflBrackets: [number, number][];   // шкала НДФЛ: [порогKop, ставка%]
  rcSeparateBase: {                   // отдельная база НДФЛ для части РК
    salary: boolean;                  // оклад/аванс/премия — с 2025 (п. 1.2 ст. 224, п. 6.2 ст. 210 НК РФ)
    averageEarnings: boolean;         // отпускные/больничные/доплата — с 2026 (абз. 2 п. 6.2 ст. 210 НК РФ)
  };
}
// Строка года может быть частичной: значения, ещё не установленные законом,
// просто отсутствуют и разрешаются из ближайшего предыдущего года.
const YEAR_SETTINGS: Record<number, Partial<YearSettings>> = {
  2024: { mrotKop, workInjuryMonthlyBenefitKop, ndflBrackets, rcSeparateBase },
  2025: { … },
  2026: { … },
  2027: { ndflBrackets, rcSeparateBase }, // МРОТ/база/кап травмы — ещё не установлены
};
const CONTRIBUTION_BASE_BY_YEAR: Partial<Record<number, number>> = { 2022, 2023, 2024, 2025, 2026 }; // коп/год
export const RC_BASE_BRACKETS: [number, number][]; // 13% до 5 млн, 15% свыше — константа закона
```

Значения `rcSeparateBase`: 2024 — `{ false, false }`, 2025 — `{ true, false }`, 2026–2027 — `{ true, true }`.

Разрешение — per-field: `getYearSettings(year)` возвращает **полный** объект, где каждое поле берётся из ближайшего года ≤ clamp(year, minKey, maxKey), в котором оно задано (обход назад; 2024 полный, поэтому обход всегда сходится). Аналогично `getContributionBase(year)` для серии баз.

- Все суммы в **копейках** (единая единица; рублевые таблицы `sickLeaveLimits.ts` переводятся при переезде).
- Предельные базы взносов — отдельная серия 2022–2026, а не поле `YearSettings`: лимит СДЗ года N использует базы (N-1) и (N-2), т.е. серия смещена на 2 года и заходит за пределы поддерживаемого диапазона. Для СДЗ 2027 нужны базы 2026 и 2025 — обе заданы, база 2027 не требуется (она понадобится только для СДЗ 2028).
- `RC_BASE_BRACKETS` — именованная константа модуля, а не поле каждого года: закон зафиксировал её на шкале 2024 для всех лет (п. 6.2 ст. 210 НК РФ), дублировать в каждой строке не нужно.
- Знаковые значения 2027 (на 14.08.2026): шкала НДФЛ — та же, что 2025–2026 (прогрессивная шкала ФЗ-176 без sunset); `rcSeparateBase` — `{ true, true }` (правило действующее). МРОТ 2027 — закон о бюджете-2027 (ноябрь–декабрь 2026), база взносов 2027 — постановление Правительства (октябрь 2026), кап травмы 2027 — индексация с 01.02.2027; до установления поля разрешаются из 2026.

Альтернативы:
- Полные строки (все поля обязательные) — отклонено: 2027 нельзя добавить, пока не выйдут все нормативные акты; per-field fallback точнее отражает реальность «закон устанавливает значения в разное время».
- Отдельная «базовая» строка-наследник, которую потом года переопределяют — отклонено: неявное наследование хуже явной частичной строки.

### D3. Потолок по травме зависит от даты, а не только года

Индексация с 1 февраля ⇒ январь года N считает по (N-1). Аксессор принимает дату:

```ts
export function getWorkInjuryMonthlyCapKop(date: PlainDate): number {
  const year = date.month === 1 ? date.year - 1 : date.year;
  return 4 * getYearSettings(year).workInjuryMonthlyBenefitKop;
}
```

В `sick-leave.ts` кап применяется к ежемесячному чанку (чанк = один календарный месяц, `ymKey`) — берём месяц/год чанка.

Альтернатива: всегда календарный год — отклонено по решению пользователя (точность января).

### D4. `ndfl.ts` читает шкалы из реестра

`getNdflConfig(year)` → `getYearSettings(year).ndflBrackets`; `RC_BASE_BRACKETS` импортируется из `yearSettings.ts`. Локальные `NDFL_PROGRESSIVE_1/2` и `NDFL_CONFIGS` удаляются. Fallback для годов вне таблицы: clamp на [minKey, maxKey] + per-field разрешение (ранее: 2023 → шкала 2024, всё ранее 2023 → шкала 2025; новое поведение последовательнее, на поддерживаемый диапазон 2024–2026 не влияет).

Опция `NdflRcOptions.rcBaseFromYear?: number` заменяется на `separateRcBase?: boolean`: `ndfl.ts` не знает категории выплат (это знание расчётного слоя — `RawEvent.type`), поэтому решение «выносить ли часть РК в отдельную базу» принимает `index.ts` и передаёт готовый флаг. Условие `year >= rcBaseFromYear` из `ndfl.ts` исчезает.

### D5. `sickLeaveLimits.ts` остаётся, но становится тонким

Формулы лимитов СДЗ (MIN = МРОТ × 24 / 730, MAX = (база(N-1) + база(N-2)) / 730) и `getSickLeaveLimits(year)` остаются в `sickLeaveLimits.ts` (это производные расчёты, не данные); данные берутся из `yearSettings.ts`. Имя функции не меняется — тесты и потребители не трогаем.

### D6. Отдельная база РК — матрица «год × категория», а не «год начала»

Хардкод `rcBaseFromYear = 2026 : 2025` в `index.ts` заменяется полем `rcSeparateBase` в таблице (D2): для каждого года явно указано, к каким категориям выплат отдельная база применяется. В `index.ts`:

```ts
const category = AVERAGE_EARNINGS_PAYMENT_TYPES.has(event.type) ? "averageEarnings" : "salary";
const separateRcBase = getYearSettings(currentYear).rcSeparateBase[category];
```

Альтернативы:
- Константа `{ salary: 2025, averageEarnings: 2026 }` с проверкой `year >= from` — отклонено: это те же «два числа-границы», просто в другом месте; не видно картины по годам и не вписывается в форму «год → настройки».
- Год начала как поле каждой строки — отклонено: дублирует информацию между строками.

Матрица точнее отражает закон: в 2025 ФНС сначала требовала выделять РК и из среднего заработка, затем отозвала позицию (письма ФНС 2025), а с 2026 выделение из среднего заработка закреплено поправкой к п. 6.2 ст. 210 НК РФ (письмо ФНС от 18.02.2026 № ЗГ-35-11/1411@). Если в 2027 правило изменится — меняется одна строка таблицы.

### D7. MIN/MAX_DISPLAY_YEAR выводятся из ключей таблицы

`MIN_DISPLAY_YEAR` / `MAX_DISPLAY_YEAR` из `shared/lib/utils.ts` перестают быть захардкоженными: вычисляются из минимального/максимального ключа `YEAR_SETTINGS` (и экспортируются из `yearSettings.ts`). Потребители (`App.tsx`, `index.ts`, `CalendarProvider.tsx`) меняют только импорт. Добавление строки 2027 автоматически расширяет диапазон приложения до 2027 (календарь за 2027 подтягивается с isdayoff.ru, расчёты — с per-field fallback на 2026 для ещё не установленных значений).

Альтернатива: оставить константы в `utils.ts` + тест-синхронизация — отклонено по решению пользователя.

## Risks / Trade-offs

- [NDFL за до-2023 выплаты изменится (было: fallback на шкалу 2025)] → поддерживаемый диапазон 2024–2026; старое поведение было непоследовательным (2023 → шкала 2024, 2022 → шкала 2025); тесты покрывают 2024–2026
- [Правило января: кап травмы для января 2024 возьмёт настройки 2023 → clamp на 2024] → допустимо: до 2024 точных данных в приложении нет, fallback на ближайший год задокументирован в спеке
- [Дрейф данных при добавлении года (забудут строку)] → спека требует единый источник; clamp даёт безопасный fallback, а не ошибку
- [Два модуля знают про «копейки»-конвенцию] → все суммы реестра в копейках, конвенция зафиксирована в комментариях типов
- [2027 считается по частично устаревшим значениям (МРОТ/кап травмы 2026, пока не выйдут акты)] → допустимо: значения индексируются 01.01/01.02, после выхода акта добавляется поле в строку 2027 — и все расчёты за 2027 автоматически становятся точными; погрешность только в переходный период
- [Диапазон расширяется до 2027 автоматически] → календарь 2027 загружается с isdayoff.ru (уже работает для любого года), расчёты — с fallback; поведение зафиксировано в спеке

## Migration Plan

Один коммит, без миграции данных (все константы — в-памяти расчётные значения, localStorage не затрагивается). Изменяются импорты в `App.tsx`, `index.ts`, `CalendarProvider.tsx` (MIN/MAX из `yearSettings.ts` вместо `utils.ts`). Rollback — revert коммита.
