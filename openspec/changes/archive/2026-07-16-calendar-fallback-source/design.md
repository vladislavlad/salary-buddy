## Context

Сейчас `fetchCalendar(year)` в `calendar.ts` делает один HTTP-запрос к isdayoff.ru и парсит ответ (строка цифр → `Map<"YYYYMMDD", number>`). Если API вернул строку из одних нулей (данных за год ещё нет), карта заполняется кодами 0 — расчёты считают все дни рабочими, что неверно.

Потребители (`CalendarProvider`, расчёт выплат, отпуска, больничные) получают `Map<number, CalendarData>` через контекст и не знают об источнике данных.

## Goals / Non-Goals

**Goals:**
- Автоматически переключаться на fallback при отсутствии данных в isdayoff.ru (строка из одних нулей).
- Fallback генерирует календарь: субботы/воскресенья (код 1) + государственные праздники РФ (ст. 112 ТК РФ, код 8) + 7 дней января (коды 1–7 = код 8).
- Потребители не меняют API — получают тот же `Map<number, CalendarData>`.

**Non-Goals:**
- Поддержка плавающих праздников (Пасха и т.д.) — в ст. 112 ТК РФ только фиксированные даты.
- Кэширование fallback-календарей в localStorage.
- Настройка праздников пользователем.

## Decisions

**1. Три функции вместо интерфейса**

Вместо `interface CalendarSource { fetch(year): Promise<CalendarData> }` — три именованные функции:
- `isdayoffFetch(year)` → `Promise<CalendarData | null>` — HTTP, возвращает `null` если строка из одних нулей.
- `generateFallbackCalendar(year)` → `CalendarData` — синхронная генерация выходных + праздников.
- `fetchCalendar(year)` → `Promise<CalendarData>` — стратегия: сначала isdayoff, при `null` — fallback.

**Рационал:** Один потребитель (`CalendarProvider`), один вызывающий код. Интерфейс добавляет абстракцию без выгоды. Функции проще тестировать и импортировать по отдельности (например, fallback отдельно в тестах).

**2. Обнаружение "нет данных" — строка из одних нулей**

После `raw.replace(/\D/g, "")` проверяем `/^0+$/`. Если совпадает — данные есть, но все дни рабочие (неверно для будущего года) → возвращаем `null`, чтобы переключиться на fallback.

**Рационал:** isdayoff.ru не возвращает пустую строку или ошибку при отсутствии данных за год — он отдаёт 365 нулей. Это единственный надёжный сигнал "данных нет".

**3. Fallback — синхронная генерация**

`generateFallbackCalendar(year)` проходит по всем дням года, определяет день недели (суббота/воскресенье → код 1) и проверяет список праздников (ст. 112 ТК РФ → код 8). Не требует HTTP, мгновенно выполняется.

**4. TanStack Query — без изменений**

`CalendarProvider` продолжает использовать `queryFn: () => fetchCalendar(year)` с `retry: 2`. Fallback не считается ошибкой — это валидные данные, просто менее точные (нет переносов выходных).

## Risks / Trade-offs

- [Fallback не учитывает переносы выходных] → Правительство РФ публикует переносы приказом Минтруда. Fallback использует только фиксированные праздники + выходные по умолчанию. Расчёты будут работать, но даты выплат могут отличаться от фактических на 1–2 дня. Пользователь увидит предупреждение в UI (за рамками этого изменения).
- [isdayoff.ru может вернуть строку из нулей для существующего года] → Маловероятно: API публикует данные за текущий год заранее. Риск актуален только для будущих годов.
