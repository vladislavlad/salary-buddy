## Context

CalendarProvider загружает календари через `fetchCalendar(year)`, который сначала пробует isdayoff.ru, при отсутствии данных — генерирует fallback. Потребители не знают, какой источник использован. Легенда календаря в App.tsx (строка 153) — место для индикатора.

## Goals / Non-Goals

**Goals:**
- Пользователь видит предупреждение при использовании неофициального календаря
- Индикатор отображается справа внизу легенды, с тултипом
- Минимальные изменения в существующей архитектуре

**Non-Goals:**
- Изменение расчётной логики
- Кэширование статуса fallback отдельно от данных календаря

## Decisions

### 1. Возврат метаданных из fetchCalendar

`fetchCalendar(year)` будет возвращать `{ data: CalendarData, isFallback: boolean }`. Это единственный чистый способ передать информацию об источнике без дополнительных запросов.

**Альтернативы:**
- Отдельный вызов `isdayoffFetch` в провайдере — дублирование запроса, лишняя задержка
- Глобальный Map fallback-статусов — усложнение архитектуры ради одного флага

### 2. Хранение isFallback в CalendarContext

Добавить `fallbackYears: Set<number>` в контекст. Проще, чем менять тип `calendars`, и не требует каскадных изменений типов у потребителей.

### 3. Рендер индикатора в App.tsx

Индикатор рендерится в легенде календаря (App.tsx:153), а не внутри YearCalendar — это UI-контейнер, который уже управляет легендой. YearCalendar остаётся чистым компонентом отображения сетки.

### 4. Визуальное оформление

Тёмно-жёлтый текст (`text-yellow-600 dark:text-yellow-500`), иконка `AlertTriangle` из lucide-react, Tooltip с пояснением. Цвет соответствует семантике "предупреждение" в shadcn/ui.

## Risks / Trade-offs

- Изменение сигнатуры `fetchCalendar` затрагивает TanStack Query — нужно обновить все места использования (`useCalendarForYear`, CalendarProvider). Риск минимален: только 2 потребителя.
- Индикатор может быть не замечен при первом открытии. Митигация: цвет и иконка достаточно контрастные для привлечения внимания.
