# Storage — Delta

## MODIFIED Requirements

### Requirement: Структура идентификаторов сущностей

Система MUST присваивать каждой создаваемой сущности уникальный идентификатор по шаблону `{тип}:{год}:{порядковый_номер}`. Порядковый номер начинается с 01 и для каждого нового объекта в рамках года равен максимальному существующему порядковому номеру за этот год плюс 1. Порядковый номер удалённой сущности не переиспользуется.

| Сущность | Шаблон ID | Пример |
|---|---|---|
| Запись об окладе | `sal:{year}:{seq}` | `sal:2026:01` |
| Премия | `bon:{year}:{seq}` | `bon:2026:03` |
| Отпуск | `vac:{year}:{seq}` | `vac:2026:01` |
| Больничный лист | `sick:{year}:{seq}` | `sick:2026:02` |
| Доплата | `sur:{year}:{seq}` | `sur:2026:01` |

Год в идентификаторе — год даты вступления в силу (для оклада и доплат) или год начала периода (для премий, отпусков, больничных).

#### Scenario: Нумерация внутри года

- **GIVEN** в 2026 уже есть отпуск `vac:2026:01`
- **WHEN** пользователь создаёт второй отпуск в 2026
- **THEN** присвоен ID `vac:2026:02`

#### Scenario: Сброс нумерации в новом году

- **GIVEN** последний отпуск 2025 — `vac:2025:05`
- **WHEN** пользователь создаёт первый отпуск 2026
- **THEN** присвоен ID `vac:2026:01`

#### Scenario: Неиспользование номеров после удаления

- **GIVEN** в 2026 два отпуска: `vac:2026:01` и `vac:2026:02`
- **WHEN** пользователь удаляет `vac:2026:01` и создаёт новый отпуск в 2026
- **THEN** новому отпуску присвоен ID `vac:2026:03`
