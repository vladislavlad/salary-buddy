# Code Review Fixes — синхронизация спеков с кодом

## Why

По итогам код-ревью проекта внесены исправления, изменившие externally-наблюдаемое поведение в трёх местах. Требования в основных спеках перестали описывать фактическое поведение системы и требуют синхронизации.

## What Changes

- **import-export**: импорт больше не очищает хранилище перед записью — каждая секция заменяется полной записью (запись массива заменяет весь массив, запись настроек — весь объект). Результат «полная замена» сохраняется, меняется порядок операций и исчезает риск потери данных при сбое на этапе очистки.
- **calendar**: при сетевой ошибке (запрос к isdayoff.ru не удался, повторные попытки исчерпаны) система больше не остаётся без календаря — для этого года используется локальный fallback-генератор, флаг `isFallback = true`.
- **storage**: порядковый номер ID сущности теперь равен максимальному существующему номеру за год плюс 1 (ранее — количеству объектов плюс 1). Номера удалённых сущностей не переиспользуются, коллизии ID после удаления исключены.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- **import-export**: требования «Импорт из JSON с полной заменой», «Порядок операций при импорте»
- **calendar**: требования «Загрузка данных календаря», «Отслеживание источника данных календаря»
- **storage**: требование «Структура идентификаторов сущностей»

## Impact

- **Affected files**: `openspec/specs/import-export/spec.md`, `openspec/specs/calendar/spec.md`, `openspec/specs/storage/spec.md`
- Код уже реализован и проверен (lint + tsc + тесты) в рамках исправлений код-ревью; данное изменение синхронизирует только спеки.
