## Context

- Диапазон лет вычисляется из таблицы `yearSettings` (`MIN_DISPLAY_YEAR`/`MAX_DISPLAY_YEAR` = min/max ключей). Сейчас таблица 2024–2027, поэтому навигация и расчёты ограничены 2024–2027.
- Календарь грузится в `CalendarProvider` через TanStack Query: `fetchCalendar(year)` → `isdayoffFetch(year)` (API) либо `generateFallbackCalendar(year)`. `CalendarData = Map<дата, код>`.
- `isdayoff.ru` по умолчанию смешивает ковидные (карантинные) дни с обычными выходными (код 1). С параметром `covid=1` API возвращает их отдельным кодом 4 (проверено: 2020 — 29 дней, 2021 — 7 дней, 2022–2023 — нет).
- Побочный эффект: для 2020–2021 API возвращает госпраздники как код 1, а не 8 (кода 8 в этих годах нет вообще). `isOfficialHoliday` (код 8) из-за этого не срабатывает → ломается продление отпуска на праздники.

## Goals / Non-Goals

**Goals:**
- Поддержка расчёта и навигации за 2020–2023 (конфиг на 2020–2027).
- Ковидные дни (код 4) в режиме «без учёта» считаются рабочими и не отрисовываются.
- Настройка приложения «учитывать ковидные дни» введёна и persisted (по умолчанию «нет»).
- Корректный код 8 для госпраздников 2020–2021 (продление отпуска работает).

**Non-Goals:**
- Режим «с учётом ковидных дней» (отрисовка ковидных дней, их учёт как нерабочих) — будущая доработка.
- Переносы выходных за 2020–2021 не моделируются дополнительно (API уже их возвращает как код 1).
- UI для изменения настройки «учитывать ковидные дни» — будущая доработка (вместе с режимом «с учётом»).
- Изменение расчётных формул (`features/payments/model/calculation/`) — не трогаем.
- **Доработка на будущее:** внутригодовое изменение значений настроек (напр. МРОТ 2022: 13 890 → 15 279 с 01.06) — сейчас одно значение на год (на 01.01). Доработка: хранить значение как массив `[{датаНачала, сумма}, ...]` и разрешать по дате. Не реализуется в этом изменении.

## Decisions

### 1. Расширение `yearSettings` до 2020–2027

Добавить строки 2020, 2021, 2022, 2023 в `YEAR_SETTINGS` (МРОТ, `workInjuryMonthlyBenefitKop`, `ndflBrackets`, `rcSeparateBase`) и расширить `CONTRIBUTION_BASE_BY_YEAR` назад до 2018 (лимиты СДЗ года N используют базы (N-1) и (N-2), поэтому для СДЗ 2020 нужны базы 2019 и 2018).

- Диапазон (`MIN_DISPLAY_YEAR`) пересчитается автоматически до 2020 — отдельные константы не меняем.
- 2020 — первая строка, она MUST быть полной (весь `YearSettings`), т.к. `resolveField` обходит от года назад до min.
- 2022 МРОТ — значение на 01.01.2022 (13 890 ₽), по конвенции «начало года» как у остальных строк; внутригодовое повышение (с 01.06.2022 — 15 279 ₽) для годового уровня не учитывается.
- Шкалы НДФЛ: 2020 — плоские 13% (`[[Infinity, 13]]`); 2021–2023 — 13% до 5 млн, 15% свыше (как 2024). `rcSeparateBase` для 2020–2023 — `{ salary: false, averageEarnings: false }`.
- В `yearSettings` добавить конфигурацию праздничных дней по годам (список дат, код 8; для 2020–2027 — праздники ст. 112 ТК РФ: 1–6 января и 8 января, 23.02, 08.03, 01.05, 09.05, 12.06, 04.11) и функцию получения списка для года (см. решение 4).

Значения (см. таблицу в spec `year-settings`): МРОТ и шкалы НДФЛ подтверждены; предельные базы взносов 2018–2021 (1 020 000 / 1 150 000 / 1 292 400 / 1 565 000 ₽) и макс. выплата по травме 2020–2023 (79 602,38 / 83 502,90 / 90 517,14 / 101 288,68 ₽) подтверждены первоисточниками (постановления Правительства РФ от 29.01.2020 № 61, от 28.01.2021 № 73, от 27.01.2022 № 57, от 30.01.2023 № 119).

### 2. Обработка ковидных дней

- `isdayoffFetch(year)` добавляет в URL параметр `covid=1` и возвращает «сырые» коды, включая код 4. Маппинг кода 4 в этой функции не делается (сохраняем информацию о ковидном дне для будущего режима «с учётом»).
- `fetchCalendar(year, accountForCoronavirus: boolean)` делает пост-обработку сырых данных:
  - если `!accountForCoronavirus` (единственный реализуемый режим) — каждый код 4 заменяется на 0 (рабочий день);
  - (будущее) если `accountForCoronavirus` — код 4 остаётся/отображается как нерабочий.
- Итог для текущего режима: ковидные дни становятся рабочими, `isDayOff` для них возвращает `false`, `DayCell` рисует их как обычные рабочие дни (без отдельной отметки) — «никак не отрисовываем».

Альтернатива (отклонена): маппить код 4 → 0 прямо в `isdayoffFetch`. Отклонено, т.к. теряется признак ковидного дня, который понадобится для режима «с учётом».

### 3. Хранение и подача настройки

Настройка календарная по смыслу, поэтому живёт в фиче `calendar` по слоям:
- `shared/types` — тип `CalendarSettings { accountForCoronavirusDays: boolean }` + zod-схема.
- `features/calendar/repository` — `CalendarSettingsRepository` (интерфейс) и `LocalStorageCalendarSettingsRepository` (имплементация, ключ в localStorage).
- `features/calendar/model` — `CalendarSettingsProvider` + контекст (загружает настройку, по умолчанию `false`), `features/calendar/hooks` — `useCalendarSettings`.
- В `app/AppProviders` провайдер настройки оборачивает `CalendarProvider`; `CalendarProvider` читает `accountForCoronavirusDays` и передаёт в `fetchCalendar`. Ключ запроса TanStack Query включает значение настройки, чтобы календарь перезагрузился при её смене.
- Настройка внутренняя: UI для её изменения не создаётся (реализован единственный режим, переключать нечего); persisted — для совместимости с будущим режимом «с учётом». В экспорт/импорт JSON не включается (не пользовательские данные).

Альтернатива (отклонена): добавить поле в существующие `SalaryPaymentSettings`/`SickLeaveSettings`. Отклонено — настройка относится к календарю, а фичи по правилам не склеиваются.

### 4. Наложение праздничных дней поверх календаря

Проблема: для 2020–2021 провайдер (isdayoff.ru) возвращает госпраздники как код 1, а не 8 → `isOfficialHoliday` не срабатывает, ломается продление отпуска.

Решение — конфигурация + наложение (по инициативе пользователя):
- В `yearSettings` хранится список праздничных дней года (решение 1).
- В пост-обработке `fetchCalendar` (после загрузки из любого провайдера) наложить эту конфигурацию: каждому праздничному дню года установить код 8, независимо от кода провайдера.

- Подход провайдер-независимый и общий: работает для isdayoff и любого другого провайдера, для всех поддерживаемых годов.
- Для 2022+ (где API уже возвращает код 8) наложение идемпотентно; для 2020–2021 чинит код 1 → 8.
- Операция независима от маппинга кода 4 (праздники — код 1, ковидные — код 4), порядок не важен.
- Fallback-генератор (`calendar-fallback.ts`) сейчас использует ошибочный список «1–7 января» (выдаёт код 8 для 7 января и код 0 для 8 января, когда оно будний: 2020, 2021, 2024, 2025, 2026, 2027). Наложение одностороннее (только установка кода 8) и не может снять чужеродный код 8, поэтому список праздников в fallback приводится к тому же значению: 1–6 января и 8 января (изменения кода и main spec «Государственные праздники РФ в fallback»).
- Альтернатива (отклонена): захардкодить список праздников и переклассифицировать только в «деградированных» годах. Отклонено — конфигурация в `yearSettings` чище, провайдер-независима и расширяема.

## Risks / Trade-offs

- [Лимит травмы за январь 2020] → резолвится в строку 2020 (макс. выплата 79 602,38 ₽, действует с 01.02.2020) вместо 77 283,86 ₽, действовавшего до 31.01.2020: завышение лимита ~3% только за январь 2020. Строка 2019 в `YEAR_SETTINGS` недопустима — унесла бы `MIN_DISPLAY_YEAR` в 2019. Принято как допустимое искажение (по модели МРОТ 2022).
- [2022 МРОТ внутри года менялся (13 890 → 15 279)] → в таблице одно значение (01.01.2022); минимальный лимит СДЗ за 2022 считается от 13 890. Небольшое занижение, допустимо для годового уровня; полное решение — доработка «массив `[{датаНачала, сумма}]`» (см. Non-Goals).
- [Режим «с учётом ковидных дней» не реализован] → настройка введена, но поведение пока всегда «без учёта»; при будущей доработке добавляется ветка в `fetchCalendar` и отрисовка в UI без изменения структуры.
- [Асинхронная загрузка настройки vs синхронный старт загрузки календаря] → по умолчанию `false` (совпадает с единственным режимом), ключ запроса включает настройку; при поздней загрузке результат не меняется, т.к. режим один.
- [Наложение праздников поверх календаря] → если конфигурация праздников в `yearSettings` расходится с данными провайдера, конфигурация выигрывает (устанавливает код 8). Для поддерживаемых годов список = праздники ст. 112 ТК РФ, поэтому расхождений с корректным провайдером нет (наложение идемпотентно).
