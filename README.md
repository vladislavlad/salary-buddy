# Salary Buddy

Клиентский калькулятор зарплаты с учётом НДФЛ, производственного календаря РФ, премий, доплат, отпусков и больничных.

## Приложение

[Salary Buddy на GitHub Pages](https://vladislavlad.github.io/salary-buddy/)

## Что делает приложение

Salary Buddy рассчитывает календарь выплат на год:

- авансы и зарплаты;
- ежемесячные доплаты;
- премии (в окладах или фиксированные);
- отпускные по ТК РФ;
- больничные: пособие от работодателя и СФР, доплата до оклада, все типы причин (ст. 7 ФЗ-255, ст. 9 ФЗ-125);
- НДФЛ по прогрессивной шкале 2026;
- перенос дат выплат с выходных и праздников на предыдущий рабочий день.

Пользователь может подтвердить или изменить фактическую gross-сумму платежа – приложение пересчитает НДФЛ для последующих выплат.

**Приложение работает как SPA без бэкенда. Данные сохраняются в `localStorage` браузера!**

## Экспорт / импорт данных

Все данные можно экспортировать в JSON-файл и импортировать обратно. Совместимость со старыми форматами не поддерживается.

## Управление данными

Решение от 25.10.2026: TanStack Query отвечает за чтение асинхронных источников и синхронизацию их данных с React. Это общий подход для списков, настроек и внешних календарей. Провайдеры открывают доступ к данным фич, application services проверяют изменения и сохраняют их через репозитории. Репозитории передаются из `AppProviders`.

Для локальных данных используются общие `LOCAL_QUERY_KEY` и `LOCAL_QUERY_OPTIONS`. Режим `networkMode: "always"` позволяет читать и обновлять их без интернета, `retry: false` отключает автоматические повторы при ошибке локального чтения. Календари загружаются отдельно со своими настройками сети и повторов. TanStack прямо предусматривает такой [режим для локальных асинхронных хранилищ](https://tanstack.com/query/latest/docs/framework/react/guides/network-mode).

После успешного сохранения хук ожидает обновление своего запроса. После импорта обновляются все запросы с локальным префиксом, без повторной загрузки календарей. Отдельную копию данных репозитория в `useState` не создаём: React-состояние остаётся у форм, диалогов и расчётного read model выплат. Это сохраняет единый механизм обновления данных вместо нескольких независимых реализаций через `useEffect`.

Частичные обновления настроек выполняются последовательно по экземпляру репозитория, включая вызовы из разных сервисов. Каждое обновление читает последнее сохранённое состояние, объединяет изменения, валидирует и сохраняет результат; ошибка не останавливает очередь. `loading` провайдеров покрывает первичное чтение и обновление (`isFetching`), поэтому расчёт выплат ждёт завершения загрузки всех исходных данных, включая настройки больничных. На один граф репозиториев используется один `QueryClient`, в тестах создаётся отдельный клиент.
