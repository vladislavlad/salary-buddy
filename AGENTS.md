# AGENTS.md – Salary Buddy

## Обзор

Salary Buddy – React SPA для расчёта дат и сумм выплат в РФ: оклад, аванс, зарплата, доплаты, премии, отпускные, больничные, НДФЛ, производственный календарь.
Бэкенда нет. Данные пользователя хранятся в `localStorage`.
Подробные спецификации проекта в формате OpenSpec — `openspec/specs/`.

## Структура проекта

Проект организован по фичам. Новые файлы класть в `src/features/<feature>` по слоям: `model`, `hooks`, `repository`, `ui`.

```text
src/
├── app/                      # provider tree, wiring репозиториев
├── features/                 # самостоятельные фичи
│   ├── bonus/                # премии
│   ├── calendar/             # производственный календарь
│   ├── import-export/        # экспорт/импорт JSON
│   ├── payments/             # расчётный read model выплат
│   ├── salary/               # оклад, история изменений
│   ├── salary-payment-settings/  # настройки выплаты
│   ├── sick-leave/           # больничные листы
│   ├── surcharge/            # доплаты
│   └── vacation/             # отпуска
├── shared/                   # общие утилиты, типы, UI primitives
├── __tests__/                # тесты
├── App.tsx
└── main.tsx
```

**Не создавать** top-level папки `components`, `context`, `hooks`, `lib`, `services`, `types`, `entities`.

### Правила слоёв

- **`model`** — services, providers/context, доменные правила; валидация → сохранение.
- **`hooks`** — публичные React-хуки; расчётные правила сюда не выносить.
- **`repository`** — интерфейс + localStorage impl, именование `LocalStorage...Repository`.
- **`ui`** — данные через props/hooks, без логики и прямого доступа к storage.
- **`shared/`** — только то, что используют несколько фич.

### Состояние и асинхронные данные (решение от 25.10.2026)

- TanStack Query — единый механизм чтения асинхронных источников: локальных репозиториев и внешних производственных календарей. Отсутствие бэкенда не ограничивает его применение.
- Локальные запросы используют общий префикс `LOCAL_QUERY_KEY` и `LOCAL_QUERY_OPTIONS`: `networkMode: "always"`, `retry: false`. Доступ к данным пользователя не зависит от интернета; сетевые календари сохраняют отдельную политику загрузки и повторов.
- Данные репозиториев не дублировать в `useState`/`useEffect`. Локальное состояние React оставлять для форм, диалогов и расчётного read model выплат.
- Хуки организуют чтение и обновление кэша. Валидация и запись выполняются application service → repository; после успешной записи хук ожидает инвалидацию соответствующего запроса.
- Частичные обновления настроек сериализовать по экземпляру репозитория: чтение актуальных данных → объединение → валидация → сохранение. Ошибка одной операции не блокирует следующие.
- После импорта обновлять все локальные запросы; производственные календари при этом не перезагружать. `loading` провайдеров покрывает первичное чтение и обновление (`isFetching`). Пересчёт выплат допустим только после завершения загрузки всех входных данных, включая настройки.
- Репозитории собираются в `AppProviders` и передаются провайдерам пропсами. Один граф репозиториев соответствует одному `QueryClient`; в тестах использовать отдельный клиент.

## Критические ограничения

### Расчётную логику не менять без отдельного запроса

Файлы `features/payments/model/calculation/` и `ndfl.ts` – ядро расчёта. 
Любое изменение формул, распределения, НДФЛ или отпускных только по прямому запросу пользователя.

### UI не менять при архитектурных рефакторингах без отдельного запроса

Если задача касается архитектуры, типов, слоёв – визуальную часть трогать не нужно.

### Payments – read model

Платежи рассчитываются и не редактируются напрямую. Пользователь может только установить фактическую сумму платежа.
В UI вводим net, приложение рассчитывает gross и сохраняет его в `Payment.fact`. Отдельного хранилища PaymentFacts нет.

### Import/export

Совместимость со старыми форматами не нужна. Не добавлять legacy adapters, runtime migrations и fallback-чтение старых ключей без отдельного запроса.

### Git: коммитить и пушить только по запросу

Не коммитить и не пушить изменения самостоятельно.

## Тесты

- В тестах доменной логики и provider/service API – **не использовать** настоящий `localStorage`. Использовать mock или InMemoryRepository.
- `localStorage` допустим только в тестах конкретной localStorage implementation или import/export storage.

## Конвенции кода

- Строгий TypeScript, без `any`.
- Именованные экспорты по умолчанию.
- `camelCase` – переменные и функции; `PascalCase` – компоненты и типы.
- `zod` для валидации пользовательского ввода и данных из persisted storage.
- TanStack Query — для асинхронных данных по правилам раздела «Состояние и асинхронные данные».
- Комментарии только на русском языке, только когда без них непонятно.
- После изменений кода запускать `pnpm lint` и `pnpm test:run`.
